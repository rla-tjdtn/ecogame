# 에코포비아 성능·안정성 최종 보고서 (측정 담당)

작성 2026-11-24. 모든 숫자는 Studio 에서 실제로 잰 값이고, 모든 시험은 음소거했다. 원본 결과는 측정 담당 scratchpad\res\<태그>-<항목>.txt 에, 기준선 상세는 [baseline.md](baseline.md) 에 있다.

## 1. 측정 방법

- **같은 맵에서 비교**: 맵·괴물 폴더를 20:36 에 얼려 두었다. 전/후 빌드는 코드만 다르다(`tools/perf-build.sh <out> <freezeDir> [overlay]`, 빌드에 쓴 src 사본은 scratchpad\src-<태그>).
- **Studio 여러 창**: 빌드마다 테스트 포트를 넣어(ServerStorage.TestPort, `tools/perf-port.js`) 창마다 따로 테스트를 받는다. 기능·회귀 시험은 여러 창에서 동시에 돌렸다. **시간 측정은 혼자**, 또는 전/후 짝을 같은 순간에 돌렸다. RAM 이 16GB 라 동시에 2창까지 연다.
- **판단 기준**: Studio 플레이는 서버와 클라이언트가 한 프로세스다. 화면 프레임 시간은 잡음이 크다. 그래서 Lua 시간(프레임당 이동+음파+선 갱신), 음파 1개 CPU, 시스템별 ms/초를 주로 본다.
- **stress 단계**: 가장 빽빽한 배회 지점에서 클라이언트 1개로 돌린다. 팀원 음파는 서버가 실제와 같은 SonarPulse 로 보낸다. 단계는 idle / solo / two / four / four-overlap(같은 자리) / four-chase(괴물 전부 추격) / flood-12(12발 동시).
- **실제 4클라이언트**: `multi` PLAYERS=4(창 5개). 비활성 창이라 약 15fps 로 돌기 때문에 스크립트 비용을 60fps 로 환산한다.
- **잴 수 없던 것**: 실제 휴대폰의 FPS·발열, 실제 인터넷 지연·지터(Studio 는 로컬). 대신 몰림 시험(flood-12, netflood)과 휴대폰 가벼운 모드 값(PoolSize 2000, RevealPerFrame 220, MaxRemotePulses 3)을 확인했다.
- **짝 측정의 한계**: 두 창에서 stress 를 동시에 돌리면(mapA/mapB) 프레임·Lua 최악값이 크게 흔들렸다. 그래서 짝 측정은 비용 수치(음파 1개 CPU, 개수 집계)로만 판단했다.

## 5. AI·애니메이션 (aibench 6~10장, 전/후 짝 2번)

- 잡기 판정 −20…−40%(예: 6장 배회 57.5 → 33.1 µs/프레임), 서버 Heartbeat −0.05…−0.15 ms, 클라이언트 MonsterAnim 은 프레임당 절반. 절대값은 작다.
- 처음 짝에서 배회 중 끼임이 0 → 14 로 보였지만, 같은 코드로 다시 잰 짝에서는 8 대 9 였다. 끼인 곳도 전/후 빌드 모두 같은 칸이었다(9장 아래층 y −3, 도플갱어 8·9장 한 칸). **AI 회귀 아님, 맵 모양 문제** → 레벨 디자인 세션에 전달.
- 추격·잡기·숨기·청각: core 의 괴물 검사가 전/후 모두 통과.

## 7. 메모리·누수

- 150초 soak(2장, 4명 분량 음파를 걸으며 계속): Lua 힙은 61~89 MB 사이에서 오르내리고 늘지 않는다. 인스턴스는 처음 20초 뒤로 평평하다. 끝나면 선 큐 0, 소리 1.
- 10장을 돌고 1장으로 돌아오기: 클라이언트 인스턴스 +24, 서버 −29, 메모리 +8 MB → 챕터 잔여 없음.
- 소리 남음: 후 빌드 netaudio 에서 "끝난 뒤 소리 ≤ 3" 이 7~8 로 실패했다. 하나의 순간값이라 아직 추격 중인 괴물 소리일 수 있어 검사를 고쳐 다시 쟀다(7초 넘게 산 소리 수 liveOld, 라운드를 다시 시작한 뒤 ≤ 3): 전(netB2) 통과, 후(netA2) 측정 중 — 결과 대기
