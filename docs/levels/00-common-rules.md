# 에코포비아 레벨 디자인 공통 규칙

모든 챕터 맵(`src/server/Stages/StageN.luau`, 생성기 `tools/places/*.js`)이 지켜야 하는 규칙과, 그것을 자동으로 재는 방법.
판정은 눈대중이 아니라 `node tools/level-graph.js` 의 그래프 검사로 한다.

## 1. 진행 구조(필수 목표)

- 목표: 시작(S) → 열쇠 3개(맵의 뒤지는 곳 Z 중 무작위 3곳) → 출구(E).
- 열쇠가 어느 Z 에 있을지 모르므로 **모든 Z 가 필수 목표**다. Z 하나라도 괴물 하나에 끊기면 안 된다.
- 출구는 한 칸 입구(엘리베이터·문)라서 출구 바로 앞(BFS 3칸, 괴물 둘·셋 검사는 마지막 방 6칸)은 "목표 공유 구역"으로 본다.
- 시작 방(시작 칸에서 2칸)은 괴물이 들어오지 않는 안전 구역(Config.Flower.KeepOut 45스터드, 일반 괴물도 시작점에서 멀리 등장)이라 검사에서 뺀다.

## 2. 금지

| 금지 | 자동 검사 |
|---|---|
| 시작 → 출구 길이 하나뿐 | `mincut`: 시작 → 출구를 끊는 데 괴물이 2마리 이상 필요(1이면 실패, 2면 경고 — 셋 넘게 늘리면 미로가 된다) |
| 괴물 하나가 서면 진행이 막히는 문·복도(목) | `single`: 3x3(복도 폭 전체) 괴물을 모든 칸에 세워 본다. 시작→Z, Z→출구, 시작→출구 모두 |
| 갈래가 같은 목으로 다시 모이는 가짜 다중 경로 | `single`·`mincut` 이 잡는다(갈래 수가 아니라 끊는 데 필요한 괴물 수로 잰다) |
| 괴물 대기 자리가 유일한 필수 통로 | `single`(모든 칸이 후보) + `dynamic` 의 기다림 위치 |
| 피할 수 없을 만큼 좁은 공간 | `width`: 가장 짧은 길 중 폭 1칸 비율(참고), 넓은 방·고리 수 |
| "괴물이 떠날 때까지 기다리기"가 유일한 선택 | `dynamic`: 괴물 N마리가 돌아다닐 때 갈 수 있는 Z·출구가 하나도 없는 순간이 생긴 판 ≤ 10% |
| 소품에 막힌 바닥, 앞에 설 수 없는 숨는 곳·상자 | `check-layout.js` 엄격 검사 + `reach` |

작은 한 문짜리 방(창고·사무실)은 **선택 공간**으로 괜찮다. 단 열쇠 상자(Z)는 두지 않는다 — 열쇠가 어느 Z 에 있을지 모르니 Z 는 늘 필수 목표이고, 괴물이 그 문 앞에 서면 기다릴 수밖에 없다. Z 는 문이 둘 이상인 방이나 복도·홀 벽에 둔다. 숨는 곳(L)·소품은 막다른 방에 둬도 된다.

## 3. 길의 종류

- **너무 다중이면 안 된다**(사용자 요청): 시작 → 출구는 주·보조·대체 세 갈래가 기준이다. 주 경로의 1.5배 안의 서로 다른 길이 4개 이상이고 고리가 16개를 넘으면 경고(`many`). 문을 아무 데나 뚫어 미로로 만들지 않는다.
- 주 경로(Primary): 가장 짧은 길. 약 120~145칸(약 2분).
- 보조 경로(Secondary): 다른 구역을 지나 같은 목표로 — 주 경로 대비 1.5배 안.
- 대체 경로(Alternative): 주 경로의 어느 한 곳이 막혀도 그 곳을 지나지 않고 갈 수 있는 길(= `single` 통과).
- 고리(Loop): 구역 그래프의 독립 순환 수(`zones` 의 고리). 추격을 따돌리는 데 쓴다.
- 지름길: 진행에 꼭 필요하지 않다.
- 수직 연결: 진짜 계단(1/2 칸, 구덩이 계단 s)만 센다.

## 4. 괴물을 움직이는 장애물로 보기

- `single`: 한 마리가 복도 한가운데·문 앞·갈림길에 서 있을 때.
- `pair`: 두 마리가 서로 다른 통로(5칸 이상 떨어진 곳)에 동시에 서 있을 때 시작→출구가 끊기는 비율 ≤ 3%, 각 Z→출구 최악 ≤ 8%(경고).
- `dynamic`: 스테이지 설정 수만큼 괴물이 무작위로 돌아다니고(플레이어 속도 0.6), 네 판에 한 판은 한 마리가 쫓아온다(0.75).
  플레이어 흉내는 괴물 둘레 3x3 을 밟지 않고 가장 가까운 안 뒤진 Z → 열쇠 3개 → 출구. 판마다 시드 고정(재현 가능).

## 5. 2층 건물

- 2층이 있는 챕터(2·4·6·7·10)는 1층 위에 **같은 크기의 2층**을 겹쳐 쌓는다(스테이지 파일 `Rows2`). 게임 지도(Q)도 1층·2층을 따로 보여 준다(버튼으로 바꿔 보기, 기본은 내가 서 있는 층).
- 2층은 띠 하나가 아니라 건물 대부분을 덮는 진짜 층이어야 한다(방·복도·Z). 바깥(야적장)·높은 천장(하역장·체육관·상영관)처럼 2층이 없는 곳만 벽으로 둔다.
- 계단: 1층의 `1`(0→6)·`2`(6→12) 두 칸, 양옆 벽. 2층 격자의 그 두 칸은 계단 구멍 `o`(둘레 난간), `2` 앞(1 반대쪽) 2층 칸이 도착 칸, 1층에서 그 칸은 벽(계단 밑으로 못 들어가게). `g.stairs(x, y, dx, dy)` 가 다 해 준다.
- 1층 천장은 11, 층 사이 판 11~12, 2층 바닥 12, 2층 천장 26.
- 2층은 대체 길 하나를 더하는 수직 연결이어야 하고, 주 경로를 120칸 아래로 줄이는 지름길이 되면 안 된다.

## 6. 건축·공포·음파

- 장소가 실제 장소로 읽혀야 한다(기능 구역, 사람·괴물 크기, 음파 선화로 읽히는 랜드마크 — 색에 기대지 않는다).
- 챕터마다 공간 정체성이 다르다(같은 뼈대 복붙 금지): 지하 시설=고리형 순환 + 중앙 봉인 구역, 창고=격자 랙 통로, 하수도=물길로 나뉜 평행 보행로, 병원=병동 복도 + 중앙 간호 스테이션, 미로=비정형, 호텔=객실 복도 층, 학교=교실 줄 + 2층, 유치원=작은 방 덩어리, 주차장=기둥 격자 + 경사로, 영화관=상영관 + 로비.
- 압축/해방: 좁은 복도 → 큰 방(음파 한 번에 다 보이는 크기)으로 리듬.
- 음파: 벽·바닥 경계·문틀·장애물·난간·계단이 깨끗한 윤곽으로 보이게. 소품을 빽빽하게 넣지 않는다(선 잡음). 가림·지속 시간 규칙은 바꾸지 않는다.

## 7. 도구

```
node tools/check-layout.js                 # 문자·문·계단·테두리·소품 막힘·숨는 곳 앞 칸
node tools/level-graph.js                  # 위 그래프·괴물 막기 검사(전부, 요약)
node tools/level-graph.js 3 --png out.png  # 한 챕터 + 길 지도 그림(파랑·초록·보라 = 서로 다른 길, 빨간 X = 괴물 하나로 끊기는 곳,
                                           #   빨간 점선 3x3 = 괴물 둘로 끊기는 자리, 주황 원 = 기다려야 했던 곳)
node tools/level-graph.js --json r.json    # 결과 기록(실패 좌표 포함)
node tools/map-image.js 3 out.png          # 게임 지도 스타일 그림(2층 건물은 out-2f.png 도)
node tools/cut-view.js 3 r12c5 r20c9       # 괴물을 세웠을 때 못 가게 되는 구역(글자 지도)
node tools/suggest-links.js 3              # 목·끊김을 메울 문 후보(꼭 필요한 만큼만)
node tools/studio-test.js stages 600       # Studio 실기: 스테이지마다 짓기·시작→출구 실제 길찾기(플레이어·괴물)·음파
```
